# 图语家连续播报回调隔离决策

- 执行工具 / 模型：Codex（GPT-5.6）
- 记录时间：2026-07-28 21:10:00

## 变动 1：按朗读任务隔离 Cordova 回调

- **意图：** 保证图语家在 CBoard Android 壳中连续朗读多个图卡、候选句或整句时，每一条任务都能收到自己的完成事件。
- **决策：** 保留官方 `cboard-speech-tts` 和 Web Speech 兼容接口，只把 Android 原生层的单一全局回调改为按 `utteranceId` 保存的并发映射；完成时只取出对应任务。
- **理由：** 原实现会在每次 Cordova 调用时覆盖全局回调，后一句朗读或一次引擎查询都可能夺走前一句的完成事件，导致表达播放队列停住或错序。按 Android 已有 utterance ID 关联无需新依赖，也不改变业务 API。
- **证据：** `speechSynthesis.test.js` 静态契约要求每个任务注册和移除独立回调，并禁止单一 `callbackContext` 字段回归；Node 测试 `4/4` 通过。最小 Cordova 14/API 35 工程成功安装本地插件，Gradle `:app:compileDebugJavaWithJavac` 明确 `BUILD SUCCESSFUL`。
- **生效范围：** `cboard-speech-tts` Android 原生插件的朗读和静音完成事件；不影响 CBoard Web 浏览器 TTS、微信 WechatSI、服务端 TTS、语音识别或 UI。

## 变动 2：取消、停止和销毁时收口未完成任务

- **意图：** 防止取消表达、离开页面或销毁 Cordova 插件后遗留永远不结束的回调。
- **决策：** `cancel` 改为调用 Android `TextToSpeech.stop()`，并将所有待完成任务以错误事件结束；`stop`、`shutdown` 和 `onDestroy` 使用相同收口逻辑。
- **理由：** 向 TTS 队列塞入空字符串并不能可靠代表取消，也不会清理 JavaScript 侧保持中的 Cordova 回调。显式停止并结束回调可以释放资源，同时不会把取消误报成正常播完。
- **证据：** 自动化契约覆盖 `cancel` 和 `onDestroy` 的停止与收口顺序；Android 14 隔离工程的 app Java 编译成功。完整 APK 的离线组装在 Java 编译之后因本机未缓存 `com.android.tools.lint:lint-gradle:31.7.3` 停止，未伪称 APK 生成。
- **生效范围：** Android Cordova TTS 生命周期；不改变朗读文本、语速、音色、队列顺序或上层取消按钮语义。

## 变动 3：初始化未完成时安全失败

- **意图：** 避免应用刚启动即朗读时在 TTS 引擎尚未就绪的窗口访问空对象并闪退。
- **决策：** `speak` 在读取语言、音色、语速前先检查 `isReady()`，未就绪时通过既有错误回调结束请求。
- **理由：** 原实现先调用 `mTts.setLanguage()`，后检查状态；构造器异步初始化期间 `mTts` 可能尚不可用。提前检查复用现有错误通道，不需要额外重试状态机。
- **证据：** 自动化契约验证就绪检查严格出现在第一次 `mTts` 访问之前。
- **生效范围：** Android Cordova TTS 启动竞态；不改变引擎初始化、voiceschanged 或上层降级策略。

## 变动 4：建立真实可执行的插件测试入口

- **意图：** 让 `npm test` 真正执行测试，而不是因不存在的 `spec/` 目录直接结束却被误认为通过。
- **决策：** 使用 Node 内置 `node:test`，不增加或升级依赖，不修改现有 lockfile。
- **理由：** 插件需要最小、跨平台、可复查的回归门；内置测试足以保护桥接关键契约，也避免继续依赖无人维护的 Jasmine CLI。
- **证据：** `package.json` 指向 `test/*.test.js`，测试文件读取实际 Java 源码和包脚本进行断言。
- **生效范围：** 本插件本地与未来 CI 测试；静态契约不替代 Android 真机发声、中文语音包或物理设备队列验收。
